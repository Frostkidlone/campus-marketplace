# Deployment Guide

Status: **configuration prepared, not executed on this machine.** Do not write "deployed successfully" in the report until every step below has been performed and the live URLs have been checked.

The backend is deployment-ready for a Python host (Render blueprint included as `render.yaml`). The frontend is a static Vite build that can be hosted on Vercel or Netlify; `frontend/vercel.json` and `frontend/public/_redirects` already contain the SPA rewrite needed by React Router.

---

## 1. PostgreSQL — choose one

### Option A — Neon (free cloud PostgreSQL, recommended for the report)

1. Sign up at <https://neon.tech> and create a project.
2. Copy the connection string; it looks like:
   ```
   postgresql://USER:PASSWORD@ep-xxxx.region.aws.neon.tech/neondb?sslmode=require
   ```
3. Put it in `backend/.env`:
   ```env
   DATABASE_URL=postgresql://USER:PASSWORD@ep-xxxx.region.aws.neon.tech/neondb?sslmode=require
   DB_SSL=True
   ```
4. Run:
   ```bash
   cd backend
   venv/Scripts/python.exe manage.py migrate
   venv/Scripts/python.exe manage.py seed_marketplace
   venv/Scripts/python.exe manage.py shell -c "from django.test import Client; print(Client().get('/api/health/').json())"
   venv/Scripts/python.exe manage.py test api.tests -v 2
   ```
5. `/api/health/` must return `"database": "PostgreSQL"`. Capture that output for Chapter 4.

### Option B — portable local PostgreSQL (no account, no admin rights)

```bash
bash setup_postgres.sh
```

Downloads the official EnterpriseDB Windows binaries into `tools/`, initialises a cluster, starts it on port 5433, creates `campus_marketplace`, writes `DATABASE_URL` to `backend/.env`, then runs migrate, seed, the health check, and the test suite. Stop it later with `bash stop_postgres.sh`. `tools/` is excluded from the submission ZIP.

### Option C — PostgreSQL already installed

Create a database and user, then set `DATABASE_URL` and `DB_SSL=False` as above.

## 2. Backend on Render

Prerequisite: the project must be in a Git repository hosted on GitHub/GitLab.

1. Push the project (the `tools/`, `venv/`, `node_modules/` folders are already in `.gitignore`).
2. In Render: **New → Blueprint**, select the repository. `render.yaml` creates the web service only; the database is the Neon project from step 1.
3. When prompted, paste the Neon connection string into `DATABASE_URL`.
4. Set these environment variables (the blueprint prompts for the two `sync: false` values):
   | Variable | Value |
   |---|---|
   | `CORS_ALLOWED_ORIGINS` | `https://YOUR-FRONTEND.vercel.app` |
   | `CSRF_TRUSTED_ORIGINS` | `https://YOUR-FRONTEND.vercel.app` |
   | `DEBUG` | `False` (already set) |
   | `DJANGO_SECRET_KEY` | generated by Render |
   | `DATABASE_URL` | Neon connection string |
5. Wait for the build. Open `https://YOUR-BACKEND.onrender.com/api/health/` — it must report `PostgreSQL`.
6. Create the admin account on the server (Render Shell):
   ```bash
   python manage.py seed_marketplace
   ```
   or `python manage.py createsuperuser`.

Note: Render's free web service sleeps after inactivity, so the first request can take ~30–60 seconds. Say this in the report rather than presenting it as a fault.

## 3. Frontend on Vercel

1. Import the same repository in Vercel.
2. Set **Root Directory** to `frontend`.
3. Framework preset: Vite. Build command `npm run build`, output `dist`.
4. Add environment variable:
   ```
   VITE_API_URL=https://YOUR-BACKEND.onrender.com/api
   ```
5. Deploy, then copy the production URL.
6. Go back to Render and set `CORS_ALLOWED_ORIGINS` and `CSRF_TRUSTED_ORIGINS` to that URL; redeploy the backend.
7. Open the site, register a user, create a listing, and send a message. These interactions prove the two services are connected.

Netlify alternative: build `frontend` with the same `VITE_API_URL`; `public/_redirects` handles SPA routing.

## 4. Known deployment limitations (state these honestly)

- **Uploaded images** are stored on the backend's local disk (`media/`). Render's filesystem is ephemeral, so uploads disappear on redeploy/restart. For a durable deployment, configure object storage (e.g. Cloudinary/S3) — not implemented.
- **Messaging** is REST request/response, not real-time.
- **No payments** are processed.
- Registration accepts any valid email; there is no institutional verification.
- Free tiers sleep; the first request may be slow.
- The automated test suite was run locally against the configured PostgreSQL/SQLite instance, not against the deployed service.
